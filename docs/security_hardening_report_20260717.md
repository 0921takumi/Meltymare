# My Focus セキュリティ・プライバシー堅牢化レポート

作成: 2026-07-17 / THINGx

---

## 概要

本番リリース後のプラットフォームに対し、THINGx 側で **セキュリティ・プライバシー・データ整合性の全体点検（監査）** を実施しました。会員情報の保護・決済処理の正確性・認可制御を中心に、影響の大きい箇所から順に強化を行い、いずれも修正・本番反映・動作確認まで完了しています。

以下は主な強化ポイントの要約です（技術詳細はコード・マイグレーション履歴に記録済み）。

---

## 1. 会員情報（プライバシー）の保護強化

- **ユーザーIDの匿名化**: 登録時に自動発行されるIDが、以前はメールアドレスの一部を含む形式でした。これを **メールと無関係なランダムID** に変更し、公開プロフィールURL等から個人情報が推測されないようにしました。既存の該当アカウントも差し替え可能な形で用意済みです。
- **ID変更機能の追加**: 会員がマイページから **自分でIDを自由に変更** できるようにしました（重複・不正文字・予約語のチェック付き）。
- **販売コンテンツ実体の保護**: 商品ファイルの保管先パスが、未購入者の画面データに含まれないよう修正しました。
- **決済識別子の非露出**: 注文詳細画面で不要な決済関連情報がブラウザに渡らないよう、必要な項目だけに限定しました。
- **本人確認書類の保全**: 一度承認された本人確認書類・生年月日を、再審査を経ずに差し替えられないよう保護しました。

## 2. 決済処理の正確性

- **入金反映の取りこぼし防止**: 一時的な通信・DB障害が発生した場合でも、Stripe からの再通知で購入が確実に確定するよう、再処理の仕組みを強化しました（「課金されたのに購入が反映されない」事象の予防）。
- **返金処理の整合性**: 一部返金・全額返金の金額計算、在庫数・クーポン利用枠の戻し処理を、返金内容と常に一致するよう整えました。同一通知が重複しても二重処理されない仕組みも追加しました。
- **振込金額の照合**: クリエイターへの振込確定時に、対象期間の売上合計と振込額が一致するかを自動照合し、不一致を検知・記録するようにしました。

## 3. 認可・アクセス制御

- **利用停止アカウントの制御徹底**: 利用停止・退会処理中のアカウントが、各種操作（購入・投稿・送金・応援等）を行えないよう、全ての入口で統一的に制御しました。
- **停止中クリエイターの非表示**: 利用停止中のクリエイターのページ・コンテンツが購入導線に出ないようにしました。
- **クーポンの保護**: クーポン情報が外部から一覧取得できないよう制御し、利用は正規の経路のみに限定しました。
- **コメントモデレーションの実効化**: 通報対応（コメント非表示）が確実に機能し、かつ投稿者以外による書き換えを防ぐよう整えました。

## 4. 入力・アップロードの安全性

- アップロード可能なファイル種別を用途に応じて限定しました。
- 外部からの不正なURL指定を悪用できないよう、コンテンツ審査処理を自社ストレージに限定しました。
- 各種テキスト入力にサーバー側の長さ・形式チェックを追加しました。

## 5. 通知の網羅性

- コメント・返信・レビュー・いいね・振込状況・返金・手数料変更など、**相手に伝わるべき通知** が確実に届くよう、抜けていた箇所を補完しました。

## 現在の状態

- 上記はすべて **本番環境へ反映済み** です。
- 主要な制御は、実際のアカウント（一般ユーザー／クリエイター／管理者／停止中アカウント）で **動作確認済み** です。
- データベース側の設定変更も適用手順を整備済みで、順次反映しています。

セキュリティは「一度で完全」というものではなく継続的な運用が前提ですが、今回の点検により **主要なリスク領域は網羅的に確認・強化** されました。今後も定期的な点検を継続します。
