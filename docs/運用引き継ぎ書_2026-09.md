# My Focus 運用引き継ぎ書（2026年9月納品分）

本書は、今回の改修で変わった仕様と、運営として日常的に行う作業をまとめたものです。

---

## 1. 今回の改修で変わったこと

### 販売の流れ（最重要）

| 以前 | 現在 |
|---|---|
| 出品 → 運営が承認 → 販売開始 | **写真**: 出品 → 即販売開始 → 運営が事後確認 |
| | **動画**: 出品 → 運営が承認 → 販売開始（従来どおり） |

写真は「公開する」にチェックして出品した時点で販売が始まります。運営の確認は**公開後**に行います。
動画は自動審査の手段が無いため、運営が承認するまで公開されません。

### 審査の3段階

| 操作 | 販売 | 購入済みの人のDL | 使いどころ | 元に戻すには |
|---|---|---|---|---|
| 非公開化 | 停止 | 可 | 一時的に下げたい（**クリエイターが自分で再公開できます**） | クリエイター本人 or 運営の「承認・公開」 |
| 却下 | 停止 | 可 | ガイドライン違反。クリエイターは修正して再提出できるが、**販売再開には運営の承認が必要** | 運営の「承認・公開」 |
| **配信停止（法令違反）** | 停止 | **不可** | 児童ポルノ・無修正・盗撮など。**返金対応が前提** | 「配信停止を解除」（却下状態に戻る）または「承認・公開」（完全復帰） |

- 却下・配信停止された商品は、クリエイターが自分で販売再開することはできません。
- 「非公開化」だけはクリエイターが自分で再公開できます。再公開させたくない場合は「却下」を使ってください。
- 配信停止を押すと、**公開サムネイルはストレージから削除されます**（URLを知っていれば誰でも見られる状態を残さないため）。本体ファイルは証拠保全のため残ります。解除後に販売を再開する場合は、クリエイターがサムネイルを再アップロードする必要があります。
- 配信停止した商品は管理コンソールの「配信停止」タブにまとまります。

### 再審査のルール

クリエイターが**本体ファイルまたはサムネイルを差し替えると、承認済みでも自動的に「新着・未確認」に戻ります**（承認した写真をあとから別の画像に入れ替える抜け道を塞ぐため）。写真は差し替え後も販売は止まりません。動画は再承認するまで非公開になります。

### その他の変更

- 購入者向けの領収書PDF発行（マイページ → 購入履歴 → 領収書）
- サムネイルの文字入れ・ぼかし加工
- クリエイターの販売ページURL共有（ダッシュボード上部）
- クリエイター画面から手数料の表示を削除
- 却下・配信停止・承認をクリエイターへ通知
- 商品が購入されたらクリエイターへ売上通知（サイト内通知＋メール。メールは RESEND_API_KEY 設定後に有効）
- 商品ページのサムネイルを拡大せず全体表示（余白は同じ画像をぼかして敷く）
- サムネイルの「ぼかし」を iPhone/Safari でも効くように修正（2件。canvas の filter を Safari が無視していた件と、なぞった範囲より狭い所だけ確定されていた件）
- Safari / Chrome / Edge / Android の実機エンジンで自動テストできる仕組みを追加（`tests/browser/`。手順は同フォルダの README）
- 各画面の表示速度改善

## 2. 運営が毎日やること

**管理コンソール → コンテンツ管理 → 「新着・未確認」タブ** を毎日確認してください。

- ここに出るのは2種類です。行ごとのバッジで区別できます
  - 「**販売中（事後確認）**」＝ すでに販売中だが、まだ運営が目視していない写真
  - 「**承認待ち（未公開）**」＝ 承認するまで公開されない動画。**クリエイターが待っています**ので優先してください
- 古い順に並んでいます。投稿から24時間以上経ったものは赤枠になります
- 200件を超えると最初の200件だけ表示されます（その旨の注意が出ます）
- **「販売実物」バッジのついた画像が、実際に購入者へ渡る写真です。** サムネイルではなくこちらを確認してください。「原寸で開く」で拡大できます
- 問題なければ「承認・公開」、問題があれば「却下」または「配信停止」

管理コンソールのトップに「新着出品（未確認）N件」のアラートが出ている間は、未確認の商品が販売中です。

## 3. 自動審査（AI）について — 現在は動作していません

AI審査（AWS Rekognition）は、AWSの認証情報が未設定のため**現在は動作していません。**
そのため写真は「運営の目視確認」だけが審査手段です。上記の毎日の確認を必ず行ってください。

AWSを設定すると、児童ポルノ・無修正などの明確な違反を出品直後に自動検出し、自動で販売停止します。
設定手順は本書末尾の「付録A」を参照してください。費用は1,000枚あたり約1ドルです。

## 4. 緊急時の対応

### 法令違反のコンテンツを見つけたとき

1. 管理コンソール → コンテンツ管理 → 該当商品の **「⛔ 配信停止（法令違反）」**
2. 理由を入力（記録に残ります）
3. これで販売停止・購入済みユーザーのダウンロード停止・一覧からの非表示が同時に行われます
4. **購入済みユーザーへの返金を別途行ってください**（Stripe ダッシュボードから）
5. 該当商品の売上は、クリエイターへの振込対象から自動的に除外されます

### 却下した商品を元に戻したいとき

管理コンソール → コンテンツ管理 → 「却下」タブ → 該当商品の「承認・公開」

### 配信停止を間違えて押したとき

管理コンソール → コンテンツ管理 → 「配信停止」タブ → 該当商品の「配信停止を解除」（却下状態に戻ります）または「承認・公開」（販売まで再開）。
サムネイルは削除済みなので、クリエイターに再アップロードを依頼してください。

### 購入者から「ダウンロードできない」と言われたとき

- 商品が配信停止されている場合: 購入履歴に「配信停止中」と表示されます。返金対応してください
- それ以外: 購入履歴に「納品待ち」と出ている場合はクリエイターの納品待ちです

### 通報を受けたとき

各商品ページの下部に「この商品を通報する」リンクがあり、押すと **my-focus@my-focus.jp 宛のメール**（件名にコンテンツIDが入ります）が開きます。
届いたメールのコンテンツIDを管理コンソールの「すべて」タブで探し、内容を確認して却下・配信停止を判断してください。
（通報の専用DB・管理画面はありません。メール運用です）

## 5. 本番環境の設定

Vercel の環境変数（Production）に以下が設定されています。

| 変数 | 用途 | 状態 |
|---|---|---|
| NEXT_PUBLIC_SUPABASE_URL / ANON_KEY | DB接続 | 設定済み |
| SUPABASE_SERVICE_ROLE_KEY | サーバー側DB操作 | 設定済み |
| STRIPE_SECRET_KEY / WEBHOOK_SECRET | 決済 | 設定済み |
| UPSTASH_REDIS_REST_URL / TOKEN | レート制限 | 設定済み（**状態未確認**、下の注意参照） |
| AWS_REGION / AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY | AI審査 | **未設定** |
| RESEND_API_KEY | メール送信 | **未設定** — 購入完了メール・クリエイターへの売上通知メール・納品完了メール・お問い合わせの自動返信は**一通も送信されていません**（サイト内の通知は動いています） |

**RESEND_API_KEY について**: メール送信サービス Resend（resend.com）のAPIキーです。未設定のため、これまで購入者・クリエイターへのメールは送られていません。
メール通知を有効にする場合は、Resend でアカウントを作成し、送信ドメイン（my-focus.jp）を認証したうえで、Vercel の環境変数に `RESEND_API_KEY` を追加して再デプロイしてください。

**Upstash について**: レート制限用のRedisですが、契約が切れている可能性があります。
今回の改修で「Redisが落ちても購入が止まらない」ようにしたため実害はありませんが、
ダッシュボード（upstash.com）で状態を一度ご確認ください。切れている場合、レート制限はサーバー内メモリで動くため Vercel 上では実質的に緩くなります。

その他: `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` はコードから参照されていないテスト用の値が残っています（動作に影響なし。削除して構いません）。

## 5-2. 新規登録の招待制（2026-09-24 に解除済み）

**現在は招待コードなしで誰でも登録できます。**

再び招待制に戻す／また解除する場合は、**必ず次の2か所を両方**切り替えてください。片方だけだと、画面は登録できるのにデータベース側で弾かれる（またはその逆）状態になります。

| 場所 | 招待制 ON | 招待制 OFF（現在） |
|---|---|---|
| Vercel の環境変数 `NEXT_PUBLIC_MYFOCUS_INVITE_ONLY` | `true` | `false` |
| データベース `app_settings.invite_only` | `true` | `false` |

データベース側は Supabase の SQL Editor で切り替えます。

```sql
update public.app_settings set invite_only = false, updated_at = now() where id = true;
```

環境変数を変えたあとは **再デプロイが必要**です（Vercel → Deployments → 最新 → Redeploy）。
現在のモードは、管理コンソール → 招待コード のページ上部に表示されます。

招待制を OFF にすると登録画面から招待コードの入力欄が消えます。発行済みの招待コードは残りますが使われません。

## 7. 本番反映とDBマイグレーション

### コードの反映

コードの正は GitHub の `main` ブランチです。本番（Vercel プロジェクト `my-focus`）への反映は、リポジトリ直下で

```
npx vercel --prod --yes
```

を実行します（Vercel CLI でログイン済みであること）。

### DBマイグレーションの適用状態を確認する

リポジトリの `supabase_migration_v*.sql` は **Supabase SQL Editor で手動実行**するものです。今回の改修分（v55〜v59）が適用済みかは、SQL Editor で以下を実行して確認できます。

```sql
select
  (select count(*) from information_schema.columns
     where table_name = 'contents' and column_name in ('requires_admin_review','hard_takedown','ai_verdict','moderated_at')) as cols_expected_4,
  (select count(*) from pg_proc where proname = 'submit_moderation_result') as overloads_expected_1,
  (select prosrc like '%v59(b)%' from pg_proc where proname = 'protect_contents_moderation_columns') as v59_applied,
  (select count(*) from pg_policies where tablename = 'contents' and policyname = 'contents_select_published') as orphan_policy_expected_0;
```

期待値: `cols_expected_4 = 4`, `overloads_expected_1 = 1`, `v59_applied = true`, `orphan_policy_expected_0 = 0`。

**注意**: 各SQLは「何度実行しても安全」と書いてありますが、**古い版を後から流し直してはいけません**（例: v59 の後に v56 を再実行すると、v59 で塞いだ穴が黙って再オープンします）。必ず番号順に、一度だけ実行してください。

## 8. 既知の事項（実害は小さいが把握しておくもの）

- **商品の保管パスが匿名でも読める**: Supabase の REST を直接叩くと、未ログインでも `contents.file_url`（非公開バケット内のパス文字列）が読めます。ファイル本体は非公開バケットで、署名URLは購入者・運営にしか発行されないため**ダウンロードはできません**。パスは `<クリエイターID>/<ランダム名>` で、元のファイル名も含みません。列単位の遮断は多数の画面が `select('*')` を使っているため今回は見送りました。
- **却下・存在しない商品ページの HTTP ステータスが 200**: 画面には「見つかりません」と出ますが、ストリーミング描画の仕組み上ステータスは 200 です。noindex は付いています。
- **振込の突合ログ**: 振込を「完了」にすると、画面の振込予定額と実際に紐付いた売上の純額を突き合わせ、不一致なら監査ログ（audit_logs / payout.reconciliation_mismatch）に残ります。振込額は画面の「振込予定額」をそのまま入力してください。

## 9. 利用規約との整合（要対応）

今回追加した「配信停止（購入済みユーザーのダウンロードも停止）」は、現在の利用規約・特定商取引法表記に**明示の根拠がありません**（規約はコンテンツの「非公開化・削除」までしか触れておらず、購入済み分の扱いと返金条件の定めがありません）。運用上は返金を前提にしていますので、以下の趣旨の条項を追加することを推奨します（文言は法務確認のうえ確定してください）。

> 案: 当サービスは、法令に違反し、または違反するおそれがあると判断したコンテンツについて、購入済みのユーザーに対する配信（ダウンロードを含む）を停止することがあります。この場合、当サービスは当該ユーザーに対し、購入代金を返金します。

あわせて、クリエイター規約 第6条の見出し「投稿コンテンツの事前審査」は、写真が事後審査になった現状と合っていません（本文は「公開前および公開後を問わず」なので内容は矛盾しません）。見出しを「投稿コンテンツの審査」に改めることを推奨します。

## 付録A: AI審査（AWS Rekognition）の設定手順

1. AWSコンソール → IAM → ユーザー → 「ユーザーを作成」
2. ユーザー名: `myfocus-moderation`（任意）
3. 「ポリシーを直接アタッチ」→ 「ポリシーの作成」→ JSON タブに以下を貼り付け

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": "rekognition:DetectModerationLabels",
    "Resource": "*"
  }]
}
```

4. 作成したユーザーの「セキュリティ認証情報」→「アクセスキーを作成」→「サードパーティサービス」
5. Vercel → プロジェクト → Settings → Environment Variables に以下を追加（Production）

| 変数名 | 値 |
|---|---|
| AWS_REGION | `ap-northeast-1` |
| AWS_ACCESS_KEY_ID | 手順4で発行されたもの |
| AWS_SECRET_ACCESS_KEY | 手順4で発行されたもの |

6. Vercel で再デプロイ（Deployments → 最新 → Redeploy）

設定後は、写真の出品直後に自動審査が走り、管理コンソールの各商品に「AI判定」バッジが表示されます。
明確な違反（Explicit Nudity 等）は自動で販売停止され、クリエイターに通知されます。
